# Sferus

Маркетплейс услуг для Приднестровья. Заказчики публикуют задания, исполнители размещают
объявления об услугах и откликаются на задания.

Коммерческий продукт, а не учебный проект. Решения принимаются с расчётом на поддержку
и рост, а не на скорость первого коммита.

## Объём v1

**Каталог услуг и доска заданий без внутреннего взаимодействия.** Связь между
пользователями — только через раскрытие контактных данных.

Вне v1: отклики · отзывы · рейтинги · чат · заказы · платежи. Не добавлять их «попутно» —
порядок и обоснование в [docs/DATA-MODEL.md](docs/DATA-MODEL.md).

Пользователь универсален: отдельных ролей «заказчик» и «исполнитель» нет.

## Стек

Next.js 16 (App Router, RSC, React Compiler) · React 19 · TypeScript strict ·
Drizzle ORM + PostgreSQL (Neon) · better-auth · Tailwind 4 + shadcn/radix ·
Resend · Biome (вместо ESLint/Prettier)

## Правила архитектуры

Полное обоснование — в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Кратко, то что нарушать нельзя:

1. **`app/**` не импортирует `db`.** Страницы читают данные только через
   `features/<domain>/queries.ts`. Страница — это композиция и роутинг, не логика.
2. **Каждый `queries.ts` начинается с `import 'server-only'`.** Без этого клиентский
   компонент может утянуть в бандл строку подключения к БД.
3. **Каждый экспорт из `'use server'` — публичный HTTP-эндпоинт.** Не «функция для моей
   формы». Обязательны: проверка сессии → проверка прав на конкретный объект → zod-парсинг.
   Порядок именно такой. Используй `authedAction` из `lib/action-client.ts`.
   Проверку прав на объект обёртка не закрывает — она остаётся строкой в теле действия.
6. **Клиентские компоненты импортируют `ActionState` из `lib/action-state.ts`**, а не из
   `action-client.ts`: тот помечен `server-only` и валит сборку при импорте из клиента.
4. **Query-функции селектят только нужные колонки.** Не `select()` целиком. Именно здесь
   решается, какие данные вообще покидают сервер — см. раздел о контактах в ARCHITECTURE.md.
5. **Фичи не импортируют компоненты друг у друга.** Общее живёт в `components/shared/`
   или `components/ui/`.

## Типы

Источник истины — схема Drizzle. Ручных «зеркальных» интерфейсов не пишем.

```ts
typeof services.$inferSelect                              // строка БД
typeof services.$inferInsert                              // вставка
z.infer<typeof createServiceSchema>                       // вход из формы
Awaited<ReturnType<typeof getServiceCards>>[number]       // то, что видит UI
```

## Команды

```bash
npm run dev            # разработка
npm run lint           # biome check
npm run db:generate    # сгенерировать миграцию после правки schema.ts
npm run db:migrate     # применить миграции
npm run db:studio      # просмотр БД
```

Перед коммитом: `npm run lint` и `npx tsc --noEmit`.

## Чего не делать

- Не писать бизнес-логику в компонентах страниц.
- Не добавлять сервисный слой / репозитории поверх Drizzle «на будущее» — порог для
  усложнения описан в ARCHITECTURE.md, до него не усложняем.
- Не менять `src/lib/db/auth-schema.ts` без необходимости — колонки там завязаны на
  плагин `admin` из better-auth.
- Не убирать проверки прав из Server Actions ради краткости.
- Не хардкодить города и категории в компонентах — только `lib/constants.ts` или БД.
