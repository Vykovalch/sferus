# Проверка новой страницы

Промт и чек-лист для приведения новой страницы к виду уже проверенных.
Собран по итогам прохода 2026-09-28 … 2026-10-01, когда через эту проверку
прошли все страницы сайта: главная, каталог услуг, страница категории, доска
заданий, карточки объявления и задания, публичный профиль, пять страниц
кабинета, семь экранов авторизации, формы размещения, экраны ошибок,
юридические документы и админка.

**Числа в чек-листе — не вкус, а то, что уже закреплено решениями владельца
в DESIGN.md.** Поэтому проверка почти всегда сводится к сверке, а не к спору.

## Чек-лист

### 1. Поверхности

| проверить | норма |
|---|---|
| холст страницы | формы и карточки объектов — `bg-background`; списки услуг, доска заданий, профиль — `bg-card`; каталог категорий — `bg-background` |
| панели и карточки | `bg-card border border-border rounded-2xl` |
| тени | **нет ни одной.** Ни `shadow-sm`, ни своей `shadow-[…]` |
| `bg-background` внутри `bg-background` | заливка панели совпала с фоном страницы — панель держится на рамке. Встречалось в профиле, кабинете, админке, юридических страницах |
| литеральные цвета | `bg-white`, `text-neutral-*` — только в подвале (единственная тёмная поверхность). В остальных местах токены |

### 2. Скругления

16px (`rounded-2xl`) у всего, что имеет контейнер. 12px (`rounded-xl`)
остался только у пунктирной плашки пустого состояния. 8px (`rounded-lg`) —
поля, селекты, строки списков внутри панелей.

### 3. Высоты и кнопки

| проверить | норма |
|---|---|
| поля, селекты, кнопки, пагинация | **40px** |
| размеры кита (`size="sm"`, `size="default"`) | не используем вовсе — дают 28 и 32px |
| главные кнопки | `h-10 rounded-full px-5`, текст 16px |
| кнопки-иконки | `h-10 w-10`; `tap-target` только для одиночных мелких отметок — у пары соседних кнопок его зоны 44px накладываются |
| осознанные исключения | сердечко (22–32px + `tap-target`), выбор города в шапке и первом экране (32px внутри чужой коробки) |

### 4. Типографика

| роль | норма |
|---|---|
| ярлык страницы (`h1`) | `text-2xl font-semibold tracking-tight`, не адаптивный |
| имя объекта (`h1`) | `text-xl md:text-2xl font-semibold` |
| заголовок блока внутри панели | **16px `font-semibold`** |
| основной текст страницы | **16px `--foreground`** |
| второстепенное: подписи, даты, счётчики | 14px `--muted-foreground` |
| подсказки под полями | 12px |
| поля ввода | 16px на всех ширинах, включая поиск в шапке |
| `font-bold` | в заголовках не используем, только `font-semibold` |

Главная ловушка: **основной текст страницы, набранный как служебный.**
Так было у описания объявления, описания задания и юридических документов —
14px серым вместо 16px основным.

### 5. Отступы и шапка страницы

- поля страницы — `py-6 lg:py-8`; на страницах с закреплённой полосой снизу
  `pt-6 pb-28 lg:pt-8 lg:pb-8`;
- крошки → `h1` — `mb-3`; `h1` → содержимое — `mb-4 lg:mb-6`
  (**неадаптивный `mb-6` — частая находка**);
- счётчик под заголовком списка: 14px, у `h1` тогда `mb-1`; при нуле
  результатов счётчика нет;
- между полями формы — `space-y-5` (20px), у пары в ряд — `gap-x-4 gap-y-5`.

### 6. Узкий экран: считать, а не смотреть

Арифметика для 375px: страница даёт **343px**, паддинг строки 16+16 —
остаётся **311px**. Дальше вычитайте обложку, плашки и кнопки. Если названию
остаётся меньше ~150px, строка сломана.

Так нашлись: 71px у «Моих услуг», 80px в админке, 145px в «Избранном».
Лечение — приём из DESIGN.md «Строка списка в кабинете»: название
в две строки, прочее строкой ниже с переносом, действия до 640px отдельной
строкой у правого края (`w-full sm:w-auto` при `flex-wrap` на строке).

Отдельно: ряды без `flex-wrap`, которые не переносятся, а вылезают за край
и дают горизонтальную прокрутку (так было у пагинации).

### 7. Закреплённые элементы

Шапка сайта — `sticky top-0 z-50`, высота **72px** на десктопе
(`HEADER_HEIGHT_PX`). Значит у закреплённого сайдбара `lg:top-24` (96px),
а не `lg:top-6`. С `top-6` верх панели уезжает под шапку — находилось
трижды: страница объявления, страница задания, публичный профиль.

В админке своей закреплённой шапки нет, там `lg:top-6` верен.

### 8. Доступность

| проверить | почему |
|---|---|
| `<input type="file" className="hidden"` | `display:none` убирает элемент из потока фокуса — загрузка недоступна с клавиатуры (WCAG 2.1.1). Нужен `sr-only` + подсветка по `focus-within` |
| `aria-label` на `<svg>` | без `role="img"` подпись объявляется ненадёжно |
| `aria-label` на `<label>` | имени не даёт: у элемента нет роли. Подпись ставят на само поле |
| плашка ошибки формы | нужен `role="alert"`, иначе отказ не объявляется |
| действие, видимое только при наведении | на сенсорных ширинах должно быть видно всегда (`sm:opacity-0 sm:group-hover:opacity-100`) |
| крупные декоративные числа и значки | `aria-hidden`, если то же сказано текстом рядом |
| голые `<Link>` в роли управления | своя обводка `focus-visible`, иначе умолчание браузера |

### 9. Контраст

**Прозрачность у текста — почти всегда ошибка.** `--muted-foreground` на 70%
по белому даёт `#888888` — **3.5:1** при норме 4.5 для мелкого текста.
Находилось в «Избранном» и на экране 500.

Исключения: неактивные элементы управления (WCAG 1.4.3 их исключает)
и декоративная графика.

Считать так: `255 − α × (255 − 85)` для серого `#555555` по белому, дальше
светлота и `(L₁ + 0.05) / (L₂ + 0.05)`.

### 10. Мёртвые классы

Находились в проекте все три вида:

- **именованная группа:** `group-hover:` не работает у кнопки кита —
  у неё `group/button`, нужен `group-hover/button:`;
- **ограничение, которое не срабатывает:** `max-w-5xl` при колонке,
  которой достаётся максимум 968px;
- **прозрачность поверх себя:** `bg-card/30` на белом холсте.

Проверять классы компилятором, а не на глаз (сниппет ниже).

### 11. Токены

- в нашей разметке — `--brand`; `--primary` оставляем компонентам кита
  (значение одно, смысл разный);
- фокус полей — `--state`; обводка иконок шапки — `--ring`. Два цвета
  фокуса, это **известная проблема 32**, не чинить молча;
- подсветка при наведении — `--muted`, но **в шапке `--accent`**: на фоне
  `--hero-bg` `--muted` даёт ступень 1.03, то есть невидим;
- `bg-white`, `text-white` вне подвала — заменить токеном.

### 12. Счётчики, пустые состояния, крошки

- счётчик под заголовком: «Объявлений: N» в категории, «Найдено объявлений: N»
  в поиске, «Заданий: N» на доске;
- пустое состояние витрины: пунктирная плашка, 16px `font-medium`
  `--foreground`, **только сообщение** — ни призыва, ни кнопки;
- пустая секция главной не показывается вовсе;
- в кабинете пустое состояние со значком и кнопкой создания — это отдельное
  решение владельца, не «выпрямлять»;
- крошки — в контейнере страницы, без отдельной обёртки.

### 13. Записи

- комментарий, который описывает прошлую правку («Изменено: …»), заменить
  на причину нынешнего состояния;
- проверить, не соврал ли комментарий или DESIGN.md: за проход нашлись четыре
  устаревших утверждения (серый холст доски и профиля в двух файлах, рамка
  сайдбара фильтров, `#565265` после смены на `#555555`);
- итог работы — запись в PROGRESS.md с измерениями и отклонёнными вариантами
  плюс пункт в «Ручные проверки», если глазами не смотрели.

## Чего не трогать без слова владельца

| что | где записано |
|---|---|
| синий у компаний и два разных зелёных | известная проблема 44 |
| два цвета фокуса (`--ring` / `--state`) | известная проблема 32 |
| ссылки внутри предложений различимы только цветом | известная проблема 41 |
| незаполненные реквизиты и жёлтые пометки `<Fill>` | решение владельца, 2026-10-01 |
| цвета сторон в «Как это работает» | отложено владельцем, 2026-09-28 |
| пустые состояния кабинета с кнопкой создания | решение владельца, 2026-09-29 |
| служебная полоса и текст пустой плашки в админке | решения владельца |
| литеральные цвета подвала | единственная тёмная поверхность |
| отсутствие кнопки удаления аккаунта | причина в коде настроек |

## Чем проверять

```bash
npx tsc --noEmit
npm test
npx biome check <изменённые файлы>
```

`npm run build` запускать **нельзя** — он начинается с миграций к боевой базе.
Сборку проверяет владелец.

**Классы Tailwind** — компилировать настоящий `globals.css`, а не голый
`@import "tailwindcss"`: без проектных токенов `border-state/60` и подобные
дадут ложный «нет». Файл со скриптом класть в корень проекта (из скретчпада
не разрешаются импорты) и удалять после:

```js
import fs from "node:fs";
import { compile } from "@tailwindcss/node";
const src = fs.readFileSync("src/app/globals.css", "utf8");
const css = await compile(src, { base: process.cwd() + "/src/app", onDependency() {} });
const out = css.build(["focus-within:ring-state/20", "sm:group-hover:opacity-100"]);
console.log(out);
```

**Порядок правил** важен, когда один класс перебивает другой
(`sm:opacity-0` против `sm:group-hover:opacity-100`): перекрывающее правило
должно идти в собранном CSS **позже**.

**Чужие сайты** — замер через браузер, а не по памяти:

```js
[...document.querySelectorAll("input")].map((el) => ({
  ph: el.placeholder,
  font: getComputedStyle(el).fontSize,
  h: Math.round(el.getBoundingClientRect().height),
}));
```

Так снят кегль поля поиска в шапке у 999.md, Ozon и Etsy. Авито и Wildberries
отдают антибот-страницу — на них не рассчитывать.

## Ловушки, на которых спотыкались

- **JSX-комментарий** нельзя ставить ни перед корневым элементом `return`,
  ни первой строкой внутри `{условие && ( … )}` — TS1005. Выносить над
  условием или писать `//` выше `return`;
- **оболочка съедает обратные кавычки** в `node -e "…"`: комментарии
  с `` `--state` `` приезжали пустыми. Писать скрипт в файл heredoc’ом
  с закрытым разделителем (`<<'EOF'`);
- **скрипты, привязанные к отступам разметки**, рвутся на файлах с другой
  вложенностью: искать по строке классов, а не по отступу;
- `searchParams` и `params` в Next 16 — **только через `await`**; синхронный
  доступ не падает, а молча отдаёт `undefined` (так теряли токен сброса
  пароля).
